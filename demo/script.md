I'm Christy, and this is joint work with Haowen and Zhen. When a coding agent finishes a turn, will the developer push back? That is what we forecast on SWE-chat, using 93 next-message targets. First, a data problem: SWE-chat's labels were noisy, often calling an ordinary follow-up request pushback. So we audited a sample by hand, turned the errors into rules in a labeling prompt, and had an LLM relabel everything; a 30-episode human check agrees on 24 of 27, versus 15 for the originals. Pushback on our targets drops from 51 to 22 percent. The task: predict the probability of pushback.

So how do we forecast it? Our idea is memory: each repository's developer has habits, so we learn them from the repo's first four sessions. A memory builder turns past reactions into rules, each backed by an exact quote; a rule becomes active only when two independent sessions agree. A ReAct critic then reads the current turn, searches that history with tools it picks itself, and outputs a pushback probability. Baselines: an LLM with no history, BM25 history in the prompt, and the same critic without memory.

So, does it work? Partly. These are results on 93 targets, 20 of them pushback; lower Brier is better. Memory helps the same critic: Brier falls from 0.303 to 0.247, and the paired interval excludes zero. But it doesn't beat a simple BM25 baseline, at 0.227. And the task is hard: AUROC is near 0.5 for every method, and all of them over-predict pushback. So memory reduces forecast error, but we haven't shown it can reliably tell which turns draw pushback.
