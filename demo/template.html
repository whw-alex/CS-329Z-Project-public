Task. Given a repository's past sessions and the coding agent's latest turn, predict P(pushback): will the developer's next message correct, reject or report a failure?
Overview

The preference-memory agent

It learns each repository's developer preferences from earlier sessions, then uses them to judge whether the coding agent's newest turn will draw pushback.

HRepository history

The repo's first 4 sessions: every developer reply, labeled pushback or not.

TCurrent turn

The developer's request and what the coding agent did (tool calls, final message).

🔒 Hidden

The developer's next message. Used only to score.

Input: what the model is given

A real turn from the data. The model sees the developer's request and what the coding agent did, plus, for the memory agent, how this developer reacted in earlier sessions. It never sees the next message.

The turn to forecast always given

What the developer asked, and what the coding agent did in response.

Hidden from the model: the developer's next message and its label. It is only used afterwards to score the forecast.
